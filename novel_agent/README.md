> 完整写作闭环：粗纲 → 细纲 → 审查 → 写作 → 校验 → 数据库维护

## 一、项目概述

基于 DeepSeek V4 Pro API 的 Python 脚本系统，实现网文创作从**粗纲生成**到**章节正文**的完整写作闭环。6 个 AI Agent 协同工作，覆盖大纲规划、细纲审查、正文写作、内容校验、设定库维护全流程。当前聚焦玄幻题材，采用交互式 CLI 工作流。

### 运行方式

```bash
pip install openai
set DEEPSEEK_API_KEY=sk-your-key
cd novel_agent
python main.py
```

### Web 界面（可选）

```bash
pip install -r webapp/requirements.txt
python -m webapp.server          # http://127.0.0.1:8765
```

书架 / 三栏写作台（细纲→审查→写作→校验→维护 实时进度）/ 设定库浏览 / 伏笔追踪 / 导出。
单并发写作任务，WebSocket 实时推送，刷新页面不丢任务状态。

### 测试脑洞

> 地球大学生林渊穿越到「魂纹世界」——这个世界的人族在十六岁成年礼上觉醒「魂纹」，魂纹决定了修炼天赋和战斗方式。林渊觉醒的是一道覆盖全身的「空白魂纹」，被所有人判定为废纹。但他很快发现，自己的空白魂纹拥有一个逆天能力——**拓印**：触碰他人的魂纹即可复制其能力。更可怕的是，他可以把多种魂纹能力组合起来，创造出闻所未闻的战斗方式。

## 三、Agent 集群架构

### 6 个 Agent 及其职责

| Agent | 职责 | 输入 | 输出 |
|-------|------|------|------|
| **粗纲生成 Agent** | 根据脑洞和设定库生成分卷叙事化大纲 | 脑洞 + 设定库 + 前卷摘要 | `VolumeOutline` |
| **细纲生成 Agent** | 根据粗纲生成任务式章节细纲 | 粗纲 + 设定库 + 前文摘要 | `ChapterOutline` |
| **小纲审查 Agent** | 检查细纲与设定库的一致性 | 细纲 + 设定库 + 伏笔 | `ReviewResult`（8 维度） |
| **章节写作 Agent** | 根据细纲生成章节正文 | 细纲 + 设定库 + 前文内容 | `ChapterContent` |
| **文章校验 Agent** | 校验正文与细纲的匹配度 | 正文 + 细纲 + 设定库 | `ReviewResult`（8 维度） |
| **数据库维护 Agent** | 从已写章节提取设定更新 | 正文 + 细纲 + 设定库 | 设定库增量更新 |

### 工作流（5 个 Phase）

```
Phase 0  项目初始化    核心脑洞 + 勾框框（分类/人称/文风/网感）→ AI 自动书名
   ↓
Phase 1  设定库初始化    AI 生成 5 库（人物/地理/历史/战力/势力），百度百科词条风格
   ↓                   人工审核编辑 + 跨库一致性检查
Phase 2  第一卷粗纲      分卷叙事化行文脉络，前 5 章背景释放计划
   ↓                   多轮修改 + 编辑器手动编辑
Phase 3  逐章写作循环    细纲 → 审查 → 写作 → 校验 → 维护（每章完整闭环）
   ↓
Phase 4  后续卷循环      基于前卷摘要 + 未回收伏笔 + 当前设定库状态继续
```

### Phase 3 单章流水线

```
细纲生成（任务式 checklist + 多轮修改）
   ↓
小纲审查（8 维度：人物/战力/地理/势力/历史/世界观/伏笔/任务完整性）
   ↓
章节写作（根据细纲生成正文 + 交互式确认/修改）
   ↓
文章校验（8 维度：任务完成度/场景覆盖度/人物一致性/设定一致性/字数/钩子/伏笔/写作质量）
   ↓
数据库维护（从正文提取新设定 + 更新已有条目 + 刷新活跃窗口）
```

## 四、核心设计原则

| 原则 | 实现方式 |
|------|----------|
| **分卷生成** | 粗纲一卷一卷写，不提前写死全书，后续可调整 |
| **行文脉络式** | 粗纲像故事梗概，叙事化、概括性强，禁止文学性描写 |
| **任务式细纲** | 每章以 ☐ checklist 形式输出任务：伏笔设下/回收、钩子、世界观释放、冲突推进 |
| **百度百科式设定库** | 5 个子库，条目式，无矛盾，跟随剧情自动演化 |
| **前 5 章释放基础** | 战力基础在前 5 章通过剧情自然交代，高级部分留后续探索 |
| **人可随时介入** | 粗纲/细纲/正文多轮修改、编辑器直接编辑 JSON、设定库手动增删改 |
| **审查校验双保险** | 小纲审查（写前检查）+ 文章校验（写后检查），确保设定一致和任务完成 |
| **设定库闭环维护** | 每章写完后从正文提取设定更新，保持设定库与剧情同步 |

## 五、比项目书新增的功能

以下功能在原始项目书基础上额外实现：

| 新增功能 | 说明 |
|----------|------|
| **AI 自动书名** | 根据脑洞生成 3 种风格书名（短/中/长），支持轻小说风长书名 |
| **编辑器手动编辑** | 粗纲/细纲可导出 JSON → 系统默认编辑器打开 → 直接修改 → 自动载入 |
| **百度百科风格展示** | 设定库条目以词条式排版展示，分字段清晰呈现 |
| **设定库自动演化** | 每章确认后 AI 自动提炼新人物/地点/势力/战力信息入库，更新已有条目状态 |
| **自动换行显示** | 所有长文本输出按 72 字符宽度自动换行，终端阅读友好 |
| **重要性分层（方案 A）** | 条目标注 core/supporting/minor，控制 prompt 注入权重 |
| **活跃窗口（方案 B）** | 仅注入最近 20 章活跃的 supporting 条目，prompt 体积随章节数增长大幅放缓 |
| **伏笔保护机制** | 出现在未回收伏笔中的角色/势力/地点，无视活跃窗口强制注入，防止遗忘 |
| **跨库一致性检查** | 自动检测人物↔势力、地理↔势力、历史↔人物之间的引用合法性 |
| **全局伏笔追踪** | 设下/回收全量记录，未回收伏笔在每章生成时提醒 |
| **小纲审查 Agent** | 写前检查细纲与设定库一致性（8 维度），防止设定矛盾进入正文 |
| **章节写作 Agent** | 根据任务式细纲生成正文，严格遵循场景流程和任务清单，支持交互式修改 |
| **文章校验 Agent** | 写后校验正文与细纲匹配度（8 维度），评分 + 问题列表 + 修改建议 |
| **数据库维护 Agent** | 从已完成正文（而非仅细纲）中提取设定更新，信息更准确完整 |
| **章节正文持久化** | 章节正文独立存储为 `chapter_contents.json`，支持加载和前文衔接 |

## 六、设定库架构

### 5 个子库

| 子库 | 内容 | 示例字段 |
|------|------|----------|
| 人物库 | 角色档案 | 姓名、别名、性别、外貌、性格、背景、能力、关系网、当前状态、重要性、最后活跃章节 |
| 地理库 | 场景地点 | 地名、类型、描述、意义、关联势力、关联人物、重要性 |
| 历史库 | 重大事件 | 事件名、时期、描述、影响、关联人物、关联势力、重要性 |
| 战力设定库 | 修炼体系 | 体系名、分类、境界列表、基础设定（前 5 章）、高级设定（后续探索）、特殊情况 |
| 势力分布库 | 宗门/帝国/组织 | 势力名、类型、描述、首领、核心成员、势力范围、势力关系 |

### 分层注入策略

```
core       → 始终注入 prompt（主角、主线反派、战力体系）
supporting → 最近 20 章活跃的注入摘要 + 伏笔关联的强制注入
minor      → 不注入 prompt，仅存设定库供查阅
```

### 自动演化机制

每章写完并确认后：
1. AI 分析正文 + 细纲 → 提炼新条目 → 百度百科风格入库
2. 更新已有条目状态（如角色战力突破）
3. 自动刷新出场条目的 `last_active_chapter` 时间戳
4. 检测与现有设定的矛盾并报告

## 七、提示词设计要点

### 粗纲 Agent 系统提示词

- 角色：玄幻小说大纲创作专家
- 分卷创作，不写死全书
- 叙事化行文脉络，禁止文学性描写（环境渲染、修饰语堆砌、氛围渲染、心理活动、具体对白）
- 每句话推进情节信息，信息密度对标电视剧分集梗概
- 必须包含：主线矛盾、成长弧线、伏笔计划、关键事件、卷末钩子
- 第一卷必须包含前 5 章背景释放计划

### 细纲 Agent 系统提示词

- 角色：章节任务规划专家
- 任务式输出：不写正文，输出"本章要完成什么"
- 必须呼应粗纲对应部分
- 固定维度：人物信息更新 / 伏笔设下 / 伏笔回收 / 结尾钩子 / 世界观释放 / 冲突推进
- 输出格式固定：章节目标 → 场景列表 → 任务清单 → 注意事项

### 小纲审查 Agent 系统提示词

- 角色：细纲审查专家
- 8 维度审查：人物一致性 / 战力体系一致性 / 地理一致性 / 势力关系一致性 / 历史事件一致性 / 世界观一致性 / 伏笔合理性 / 任务完整性
- 输出评分 + 问题列表 + 修改建议
- 评分标准：90-100 完全一致，<70 严重冲突需重新规划

### 章节写作 Agent 系统提示词

- 角色：网络小说写作专家
- 严格遵循细纲任务清单，每个任务项必须在正文中体现
- 场景驱动，按细纲场景流程顺序写作
- 文风适配（番茄爆款/科幻硬核/轻松日常/热血战斗/悬疑烧脑）
- 正文末尾附写作检查清单，供校验 Agent 验证

### 文章校验 Agent 系统提示词

- 角色：章节内容审核专家
- 8 维度校验：任务完成度 / 场景覆盖度 / 人物一致性 / 设定一致性 / 字数达标 / 钩子效果 / 伏笔落地 / 写作质量
- 验证写作检查清单中的自检项是否真正完成
- 输出评分 + 问题列表 + 修改建议

### 数据库维护 Agent 系统提示词

- 角色：设定库维护专家
- 从正文 + 细纲中提取新增设定（比仅从细纲提取更准确）
- 以百度百科词条风格撰写新条目
- 更新已有条目的最新状态
- 自动判断重要性（core/supporting/minor）
- 检测与现有设定库的矛盾

## 十一、技术栈

- **语言**：Python 3.10+
- **模型**：DeepSeek V4 Pro（OpenAI 兼容 API）
- **SDK**：openai >= 1.0.0
- **存储**：JSON 文件（人类可读，便于手动编辑）
- **运行环境**：命令行 / PyCharm
