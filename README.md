# 多 AI Agent 网络小说智能创作系统

> 完整写作闭环：粗纲 → 细纲 → 审查 → 写作 → 校验 → 数据库维护
> 支持无人值守全自动流水线、多书书架管理、多评委盲评质检与 Web 可视化界面
> 2026-08-27
> 团队：三太子团队（杨闻恺、许陈曦、张怿源）

## 一、项目概述

基于 DeepSeek V4（OpenAI 兼容 API）的 Python 多 Agent 网文创作系统，实现从**一句脑洞**到**成章小说**的完整生产线。6 个 AI Agent 协同工作，覆盖大纲规划、细纲审查、正文写作、内容校验、设定库维护全流程；配合纯代码级确定性校验与多评委盲评质检，已完成 50 章无人值守长跑验证。

核心能力：

- **6 库设定库**（人物/地理/历史/战力/势力/道具）：百度百科词条风格，随剧情自动演化，分层注入控制 prompt 体积
- **全局伏笔台账**：ID 化管理、换皮去重、回收映射与归档，未回收伏笔强制注入防止遗忘
- **三道质量防线**：写前代码级拦截（死人出场/境界词/实体名门控）→ 写后 8 维度校验 + 不过强制重写 → 多评委盲评按章漂移评估
- **四种使用方式**：交互式 CLI 向导 / 无人值守自动流水线（断点续跑）/ 非交互 CLI（供脚本、插件调用）/ 本地 Web 界面

### 示例脑洞

> 地球大学生林渊穿越到「魂纹世界」——这个世界的人族在十六岁成年礼上觉醒「魂纹」，魂纹决定了修炼天赋和战斗方式。林渊觉醒的是一道覆盖全身的「空白魂纹」，被所有人判定为废纹。但他很快发现，自己的空白魂纹拥有一个逆天能力——**拓印**：触碰他人的魂纹即可复制其能力。更可怕的是，他可以把多种魂纹能力组合起来，创造出闻所未闻的战斗方式。

配套勾选：玄幻 / 第三人称 / 番茄爆款文风 / 网感中等 / 每卷 50 章 / 每章 3000 字。

## 二、快速开始

### 安装与配置

```bash
pip install -r novel_agent/requirements.txt
set DEEPSEEK_API_KEY=sk-your-key        # Windows；Linux/macOS 用 export
```

密钥也可写入 `novel_agent/.env`（`DEEPSEEK_API_KEY=sk-...`），该文件已被 `.gitignore` 排除，不会入库。可选环境变量：`DEEPSEEK_MODEL`（默认 `deepseek-v4-flash`）、`DEEPSEEK_BASE_URL`。

### 方式一：交互式 CLI 向导

```bash
cd novel_agent
python main.py
```

Phase 0-4 完整向导：脑洞输入 + 勾框框 → 设定库生成与人工审核 → 粗纲多轮修改 → 逐章写作循环，每一步都可人工介入修改。

### 方式二：无人值守自动流水线

```bash
python auto_pipeline.py --name 我的书 --idea "脑洞描述……" --chapters 50
python auto_pipeline.py --name 我的书 --resume        # 断点续跑
```

全程逐步落盘（原子写）、伏笔台账 ID 化、确定性校验写前拦截、字数越界程序化扩写/收缩、校验不过强制重写（最多 2 次）；每章输出 JSON 审计记录，跑完生成汇总 markdown 报告与多评委按章漂移评估。

### 方式三：非交互 CLI（供脚本 / 编辑器插件调用）

```bash
python cli.py new --name 书名 --idea "脑洞描述"     # 新建：设定库 + 第一卷粗纲
python cli.py chapter                              # 生成下一章（完整流水线）
python cli.py status / export / list / use / memory
```

状态持久化在项目目录 `project.json`，跨调用可续写。

### 方式四：Web 界面

```bash
cd novel_agent
pip install -r webapp/requirements.txt
python -m webapp.server          # http://127.0.0.1:8765
```

页面：书架 / 新建向导 / 三栏写作台（章节树 · 流水线与正文实时进度 · 设定速查 + 伏笔）/ 设定库浏览 / 伏笔追踪 / 评测 / 导出。
单并发写作任务，WebSocket 实时推送，刷新页面不丢任务状态。前端 Vue3 已本地化，无需外网。

### 可选：独立评委模型

```bash
set JUDGE_API_KEY=sk-judge-key
set JUDGE_MODEL=deepseek-v4-pro
```

配置后评审切换到独立模型，与写手模型分离，避免「自己给自己打分」；未配置则复用主力模型。

## 四、Agent 集群架构

### 6 个 Agent 及其职责

| Agent | 职责 | 输入 | 输出 |
|-------|------|------|------|
| **粗纲生成 Agent** | 根据脑洞和设定库生成分卷叙事化大纲 | 脑洞 + 设定库 + 前卷摘要 | `VolumeOutline` |
| **细纲生成 Agent** | 根据粗纲生成任务式章节细纲 | 粗纲 + 设定库 + 前文摘要 | `ChapterOutline` |
| **小纲审查 Agent** | 检查细纲与设定库的一致性 | 细纲 + 设定库 + 伏笔 | `ReviewResult`（8 维度） |
| **章节写作 Agent** | 根据细纲生成章节正文 | 细纲 + 设定库 + 前文内容 | `ChapterContent` |
| **文章校验 Agent** | 校验正文与细纲的匹配度 | 正文 + 细纲 + 设定库 | `ReviewResult`（8 维度） |
| **数据库维护 Agent** | 从已写章节提取设定更新 | 正文 + 细纲 + 设定库 | 设定库增量更新 |

### 工作流（5 个 Phase）

```
Phase 0  项目初始化    核心脑洞 + 勾框框（分类/人称/文风/网感）→ AI 自动书名
   ↓
Phase 1  设定库初始化    AI 生成 6 库（人物/地理/历史/战力/势力/道具），百度百科词条风格
   ↓                   人工审核编辑 + 跨库一致性检查
Phase 2  第一卷粗纲      分卷叙事化行文脉络，前 5 章背景释放计划
   ↓                   多轮修改 + 编辑器手动编辑
Phase 3  逐章写作循环    细纲 → 审查 → 写作 → 校验 → 维护（每章完整闭环）
   ↓
Phase 4  后续卷循环      基于前卷摘要 + 未回收伏笔 + 当前设定库状态继续
```

### Phase 3 单章流水线

```
细纲生成（任务式 checklist + 多轮修改）
   ↓
写前拦截（确定性代码校验：死人出场 / 未登记境界词 / 实体名门控）
   ↓
小纲审查（8 维度：人物/战力/地理/势力/历史/世界观/伏笔/任务完整性）
   ↓
章节写作（根据细纲生成正文，字数越界程序化扩写/收缩）
   ↓
文章校验（8 维度：任务完成度/场景覆盖度/人物一致性/设定一致性/字数/钩子/伏笔/写作质量）
   ↓                校验不过 → 反馈强制重写（最多 2 次），仍不过标记 needs_attention
数据库维护（从正文提取新设定 + 更新已有条目 + 刷新活跃窗口）
```

## 五、核心设计原则

| 原则 | 实现方式 |
|------|----------|
| **分卷生成** | 粗纲一卷一卷写，不提前写死全书，后续可调整 |
| **行文脉络式** | 粗纲像故事梗概，叙事化、概括性强，禁止文学性描写 |
| **任务式细纲** | 每章以 ☐ checklist 形式输出任务：伏笔设下/回收、钩子、世界观释放、冲突推进 |
| **百度百科式设定库** | 6 个子库，条目式，无矛盾，跟随剧情自动演化 |
| **前 5 章释放基础** | 战力基础在前 5 章通过剧情自然交代，高级部分留后续探索 |
| **人可随时介入** | 粗纲/细纲/正文多轮修改、编辑器直接编辑 JSON、设定库手动增删改 |
| **审查校验双保险** | 小纲审查（写前检查）+ 文章校验（写后检查 + 强制重写） |
| **设定库闭环维护** | 每章写完后从正文提取设定更新，保持设定库与剧情同步 |
| **LLM 不可信处用代码兜底** | 死人出场、境界词、实体名一致性等硬性矛盾用纯规则在落盘前拦截 |

## 六、设定库架构

### 6 个子库

| 子库 | 内容 | 示例字段 |
|------|------|----------|
| 人物库 | 角色档案 | 姓名、别名、性别、外貌、性格、背景、能力、关系网、当前状态、重要性、最后活跃章节 |
| 地理库 | 场景地点 | 地名、类型、描述、意义、关联势力、关联人物、重要性 |
| 历史库 | 重大事件 | 事件名、时期、描述、影响、关联人物、关联势力、重要性 |
| 战力设定库 | 修炼体系 | 体系名、分类、境界列表、基础设定（前 5 章）、高级设定（后续探索）、特殊情况 |
| 势力分布库 | 宗门/帝国/组织 | 势力名、类型、描述、首领、核心成员、势力范围、势力关系 |
| 道具库 | 法宝/神器/关键物品 | 名称、类型、描述、持有者、能力、来历、当前状态 |

### 分层注入策略

```
core       → 始终注入 prompt（主角、主线反派、战力体系）
supporting → 最近 20 章活跃的注入摘要 + 伏笔关联的强制注入
minor      → 不注入 prompt，仅存设定库供查阅
```

### 自动演化机制

每章写完并确认后：
1. AI 分析正文 + 细纲 → 提炼新条目（含道具）→ 百度百科风格入库
2. 更新已有条目状态（如角色战力突破、道具易主）
3. 自动刷新出场条目的 `last_active_chapter` 时间戳
4. 跨库一致性检查（人物↔势力、地理↔势力、历史↔人物、道具↔持有者引用合法性）

### 伏笔台账

- 全局伏笔 **ID 化**登记：设下 / 回收全量记录，换皮伏笔自动去重
- LLM 辅助回收映射 + 已回收伏笔归档
- **伏笔保护机制**：出现在未回收伏笔中的角色/势力/地点/道具，无视活跃窗口强制注入 prompt，防止遗忘

## 七、质量保障体系（三道防线）

| 防线 | 时机 | 实现 | 成本 |
|------|------|------|------|
| **确定性代码校验** | 写前/落盘前 | `consistency_checker.py`：死人出场检测（含回忆/转世/闪回白名单防误报）、未登记境界词拦截、细纲名称装饰规范化、**实体名门控**（正文与设定库的名字一致性代码级比对） | 纯规则，不调 API |
| **文章校验 Agent** | 写后 | 8 维度匹配度校验 + 写作检查清单核对；不过则反馈重写（最多 2 次），仍不过标记 `needs_attention` 人工介入；字数越界程序化扩写/收缩 | 单次 LLM 调用 |
| **评委层盲评** | 章级/全书 | `judge.py`：3 档温度（0.2/0.5/0.8）多评委取中位数；评审 prompt 盲评设计避免「AI 生成」偏差；可插拔独立评委模型；提供签约标准评估、单章质量评估（长跑漂移曲线）、A/B 盲选 | 多次 LLM 调用，可独立模型 |

## 八、验证情况

- **50 章无人值守长跑**：`auto_pipeline.py` 端到端跑通，全流程无需人工介入
- 长跑整改项：节奏自然度（剧情跳跃、缺乏人味）、首发字数精度、连续爆发护栏、转世误报修复、单章任务上限代码化
- 多评委按章漂移评估 + 汇总 markdown 审计报告（每章 JSON 记录）
- 交互式流程：项目创建/设定库审核/粗纲细纲多轮修改/编辑器手动编辑均已验证
- 单元测试覆盖 Agent 逻辑、书架、Web API（mock 模型调用，离线可跑）

## 九、技术栈

- **语言**：Python 3.10+
- **模型**：DeepSeek V4 系列（默认 `deepseek-v4-flash`，OpenAI 兼容 API）
- **SDK**：`openai >= 1.0.0`
- **Web**：FastAPI + WebSocket + Vue3（本地化，无 CDN 依赖）
- **存储**：JSON 文件（人类可读，便于手动编辑与断点续跑）
- **运行环境**：命令行 / Web 浏览器
